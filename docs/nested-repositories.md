# JetTortoise 嵌套仓库

本说明描述 JetTortoise 如何处理工作区内的多层 Git/CVS 仓库：怎样登记与打开，以及父仓写操作为什么不能跨入子仓。

## 添加与打开

1. 执行 **JetTortoise：添加仓库**，选择当前受信任本地工作区内的目录。选择普通子目录时会定位其最近的实际仓根；同一路径同时具备 Git/CVS 元数据时需选择类型。
2. **打开历史** 和状态栏从已登记仓库中选择，展示类型、层级、相对路径和完整路径。每仓独立标签页，保留四栏布局，不合并父子仓的提交列表。
3. 文件历史入口先定位最近的真实边界。未登记子仓提供“添加并打开”；取消不会改用父仓。
4. **从列表移除仓库** 持久隐藏登记，下次扫描不会自动加回。现有页面和已保存状态保留，新操作被拒绝；重新添加相同仓根可继续使用。已关闭的 Git 页面没有长期保存的提交草稿。

登记记录保存在当前 VS Code 工作区的 `repositoryRegistrations` v2，包含自动/手动来源、隐藏项和发现状态。v1 原登记直接迁移，仓库 ID 与页面状态不变。旧版 `repositories` 只作为待确认候选，不能直接恢复 diff 的访问权限。恢复旧页面时取消登记会保留页面；确认登记之前操作仍被拒绝。无效、已经删除或位于窗口访问范围之外的恢复目标会报错，不能保证保留该目标的页面。

受信任工作区默认递归发现并自动登记所有层级的仓库；可关闭 `jettortoise.autoDiscoverRepositories`，保留已保存列表。忽略规则和依赖目录不会阻止发现，但不跟随目录 symlink、不扫描窗口外祖先。类型与真实根路径共同决定身份，路径别名不会产生第二个仓库。父子层级仅用于展示，不能授权父仓操作子仓。

仓库列表位于工作台第一栏，上方显示所有仓库及分支/标签，下方保留当前仓导航。右键更新或刷新其它仓库不切换当前标签；每仓队列、草稿、历史选择、diff 仍独立。完整扫描、更新和只读比较规则见 [工作台说明](./repository-workbench.md)。

## 独立打开子目录窗口

JetTortoise 只允许操作当前窗口工作区文件夹之内的仓根。打开 `platform/plugins/editor/` 时：

- 如果 `editor/` 是独立 Git/CVS 仓库，候选是这个子仓，外层 `platform/` 不会自动加入。
- 如果它只是外层仓的普通目录，不会将它伪装成独立仓库，也不会静默带入外层仓。通过添加/文件入口操作时提示真实仓根位于窗口之外；要使用外层仓，需打开仓根或把它添加为当前窗口的工作区文件夹。
- VS Code 自带 Git“源代码管理”视图由内置 Git 扩展管理。其 `git.openRepositoryInParentFolders` 设置与 JetTortoise 登记机制独立。本次没有改写用户或工作区的 VS Code 设置，也没有重新启动用户窗口。

窗口范围、未信任/虚拟工作区、已移除根及物理仓库替换均在 Host 操作前再次校验。已打开标签不会因当前编辑器或仓库列表改变而切换目标。

## 子仓保护

**真实边界决定能否写入，登记只决定能否打开。** 保护同时覆盖 Host 直接文件操作与 Git/CVS 内核入口。

| 操作 | 行为 |
| --- | --- |
| 父仓提交区 | 用独立提示列出在当前状态中遇到的或已登记的子仓，提供打开/添加入口；子仓文件不进入父仓待提交选择。工作区后台扫描会发现被 Git 忽略的子仓；提交状态查询自身不额外触发递归发现。关闭自动扫描时可手动重新扫描。 |
| 父仓历史 | 继续读取父仓自己的 Git 历史，不因当前目录成为子仓而隐藏过去的提交。 |
| 暂存、回滚、合并保存、选中文件 Shelf | 按路径重新验证归属；拒绝目录穿越、跨子仓及符号链接绕行。整个目录的操作还需检查其下级边界。 |
| 全部暂存 | 从明确的候选文件集合中跳过子仓，只暂存经过校验的父仓文件。既有暂存内容不被取消。 |
| 提交/修订/提交并推送 | 检查完整 Git 索引，包含未改变但仍被父仓跟踪的子仓条目；存在重叠就拒绝。提交区在暂存所选文件之前先检查旧索引，内核提交时再次检查。 |
| checkout/reset、merge/rebase、全量 stash 或恢复、整包 patch | 第一期开启前检查整个受影响仓树；有子仓且无法限定影响范围时拒绝。所选文件的 stash 也在重建索引之前检查完整索引。 |
| IDEA Shelf | 创建、读取、导出和删除均验证 Shelf 存储所属边界及已有 XML/patch 安全规则。Shelf 存储树本身出现子仓时会保守拒绝使用；导入文件仍由 Host 对话框选择。 |
| CVS 文件与 update | 连续工作副本子目录属于同一仓；独立 Git/CVS 子仓不进入父清单。明确文件的历史/diff/提交/回滚沿用校验，递归 update 在存在子仓时暂停。 |

CVS 连续性结合 `CVS/Root`、`CVS/Repository` 和父 `Entries` 的 `D/name/` 关系；同一服务端的独立 checkout 也可以形成新边界。不会将普通目录嵌套解释为 submodule。

全仓写操作的预检最多访问 5,000 个目录，跳过 Git/CVS 管理目录、不跟随符号链接，遇到独立子仓即停止进入该子树。无法完整读取、元数据损坏或超过限额时拒绝开始。CVS 清单保留已有 2,000 个文件/目录上限。预检是显式操作的一部分，不登记仓库，也不是后台全盘扫描。

Git 文件保存事件按真实归属刷新；只有父索引精确跟踪重叠文件时才同时刷新父仓。边界导航消息只含 Host 刚枚举的 ID，不能携带 cwd。关闭页面、移除登记、队列等待中换仓或确认期间新建子仓不能把操作转到其它仓库。

## 验证范围

`pnpm run test:headless` 中的嵌套检查使用临时真实仓库及生产源码加模拟 VS Code API，覆盖三层 Git、Git 内 CVS、CVS 内 Git、连续 CVS、同源/异源独立 checkout、登记取消与恢复、索引重叠、子仓符号链接、Shelf、确认期间新增边界和保存事件归属。

这些检查没有覆盖真实 VS Code 的层级选择器观感、窗口 Reload、安装切换与键盘焦点。也没有验证 Windows/Linux、真实 CVS 服务器、submodule/worktree 专用管理及恶意本机进程在文件检查与执行之间并发替换目录的全部竞态。现有依赖风险继续保留，见[安全审查](./security-review.md)。
